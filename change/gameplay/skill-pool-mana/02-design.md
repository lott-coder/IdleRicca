## 核心重点

在隔离 Unity 2022.3.52f1c1 工程中接入用户授权的十段源动作与对应源特效。现有技能执行只认配置目录，于是用五条新定义替换 Demo 的四条占位定义。四个装备槽各自存技能 ID 与等级，和目录容量独立。波次定卡时锁定最终预告，施放命令同时写入动作和 MP。

| 类型或文件 | 层 | 新职责 |
|---|---|---|
| `SkillId`、`SkillDefinition` | Domain | 鉴别五项新技能 ID 与现有规则配置。定义三档伤害和动画有效窗 |
| `PlayerSkillSet`、`WaveRun`、`WaveRewardPool` | Application | 不同容量、资格过滤、预告快照和领取验证。三类权重默认各 45 |
| `PlayerActions`、`PlayerCombatStatus`、`SkillStatus` | Application | MP 上限、剩余、原子扣量和选项可施放快照 |
| `RiccaSkillSettings`、`RiccaPlayer`、`SkillHitbox` | Presentation | 验证动画及源特效资源，按配置采样动作、提交站立盒或运动扫描 |
| `SkillSelectionHud`、`WaveHud`、`CombatHud` | Presentation | 反映技能名、MP 消耗、不可用原因与蓝条 |
| 隔离 Editor 导入/检查工具 | Editor 验证 | 严格导入清单、GUID 与依赖核验、修整源资源的项目绑定并生成证据 |

备选是留用固定数组并按槽位绑定五种状态的前四项。它较少改动现有奖励接口，但第五项会永远被挡在槽外。采用独立目录和领取预告方案，复用当前命令与奖励阶段。

## 1. 源动作、特效和资产边界

### 1.1 源文件校验与安装

- 来源限定在 `D:/Learning/Unity/_ricca/work/project/Assets` 的已核实资源。读原资源的路径、GUID 和 SHA-256。目标按 `Assets/Art/Demo/Ricca/SourceSkills/` 下的动作与效果分类存放，收敛到被五个技能使用的渲染依赖闭包。直接接入已有动作及粒子，不制作替代动画或特效。
- `AssetDatabase` 批量检查 GUID。主工程已有同 GUID 的资源时核对资源类型并复用，候选有差异时停在隔离工程修正引用，避免造出重复 GUID。检查源 AssetRipper 工程的 `PrefabInstance`、材质、Shader、贴图、Mesh 与 AnimationClip 链路。
- 对原动画使用 Unity Editor 校验并复制片段。保留动作关键帧和原有时长。若源事件仅调用本工程缺失的音效处理器，记录并剔除相应旧事件，技能效果时点由本项目配置控制。三个主动作的六个未知路径均对应对照中仅有的局部装饰骨骼差异。优先找得到的真实绑定。无法按源证据匹配时只清理这些无效通道，留下源文件、目标文件和差异清单，实际采样核对躯干、腿、双臂、握剑和动作曲线。
- VFX 保留原生 ParticleSystem、Renderer、Mesh、Animator/Animation 和渲染资产引用。隔离工程构建专用的纯表现 Prefab，排除源游戏脚本、控制器业务依赖和伤害组件，由当前 Application 接管伤害。新增可启停的序列化根节点字段 _effectRoot。保留旧 _effect 的 ParticleSystem 字段及原字段类型，旧配置以其 GameObject 作为根节点。新源配置绑定 _effectRoot。整组粒子按初始化时缓存的引用播放，无逐帧查找。
- 已确认匹配的视觉资源为本轮资产门禁。图形依赖无法导入时明确记录具体引用和原因，继续修复并复测。缺关键资源的技能在运行时不可抽取、不可施放。City 交付验收要求五项主技能齐全，且与技能相关的表现无粉色、失效绑定或 Missing Script。

## 2. 领域、奖励和 MP 契约

1. `PlayerSkillSet` 在构造时复制并校验目录。四槽使用独立的目录索引和等级，占位留空。通过唯一 ID 查询，Presentation 以目录 ID 取得表现缓存。旧枚举值保留内部兼容，City 配置只登记五个源技能。
2. `WaveRewardPool.Draw` 继续在类型和等级组合上无放回。允许任意正权重，Demo 配置三类均为 45。技能资格在当前组生成前读取，条件为至少有技能可授予或升级，并且本局至少能耗 10 MP。与 City 一起运行的旧无技能配置入口保持原行为。
3. 生成技能卡时用独立的目录 RNG 在所有尚未装备的有效目录项中选中候选，确定最左空槽与卡片等级。若已满，找最左的最低等级可升级槽。结果保存到本组固定的三格预告数组。不同等级的卡可以指向同一待授予技能，选择任何一格仍只消费一次。测试可注入种子，目录抽奖与三类奖励抽奖分开。
4. 领取按 `offerId`、索引、阶段和现有槽再次核校资格，并应用已锁定的 `SkillRewardPreview`。资格或目标变化时拒绝并保持状态。提交成功后推进波次，并保持既有 `SkillRewardSelected` 观察通知顺序。
5. 在 `PlayerActions` 中以当前配置的正整数最大蓝量初始化，默认 100。每次接受技能动作前校验可控、选择编号、槽位、资源就绪和 MP，接受时扣 10。保持 MP 最低为 0。无局内恢复入口，重开由既有场景初始化刷新。死亡收尾可以读取当前蓝量。技能开始后遭打断不回退蓝耗。
6. `SkillStatus` 返回剩余 MP、当前编号、四槽和可施放判据。只有至少一项可用才申请减速。已有技能但蓝量不足时，F 仍打开原速面板，按钮禁用并显示 10 MP 成本和缺蓝原因。

| 契约 | 输入和输出 | 边界 |
|---|---|---|
| `WaveRun.TryGetSkillRewardPreview(offerId,index,out preview)` | 继续返回值快照 | 已保存预告，无可写数组，旧或非技能选项安全拒绝 |
| `PlayerActions.SkillCommands.TryCastSkill(...,out cast)` | 沿用现有签名。Application 统一判断可施放和扣蓝 | 表现先校验目标技能资源，原子扣量发生在动作接纳时，过期/重复/无效请求返回 false |
| `PlayerCombatStatus.CurrentMp / MaxMp` | 非负整数及正上限 | 从 Application 到 UI，保持 HP 与连击字段及入口 |
| `SkillHitbox.Resolve` | 有效批次、几何、起止位置、固定朝向 | Unity 只回报当前批次敌人候选，Application 按敌人实例去重和扣血 |
| 序列化配置 | 旧状态继续可读 | 新蓝量值默认 100，现有波次、相机和设备入口的引用保持，单局无 schema 变更 |

## 3. 命中与生命周期

鼠标选择采用同一主线程调用栈内的预检、提交、播放顺序。先读取当前选择编号与槽位、检查接地和相机角度对应的动作状态、Animator、必要特效与伤害盒。按选技时间所有权计算关闭后将采用的缩放和固定步长，确保仍可起手。预检失败时不提交命令。通过后由 Application 一次接受选择、设定施放和扣 10 MP。提交之后不再执行可能把事务标成拒绝的检查，只释放时间所有权并立即播放已解析的状态。若已接受动作后发生外部中断，走已接受施放的取消和批次作废路径。

- 沿用归一化动画窗口和 `AttackSampleBatch`。静止盒在该有效区间进行 OBB 查询。移动盒先依据批次 PreviousProgress / Progress 与 Start / End 把本帧路径裁剪到有效窗。只对裁剪区间映射的两端检查重叠，并在其间用 PhysicsScene.BoxCast。粗时间步跨过整个窗口时仍只扫描窗口覆盖的有效子路径。候选缓冲按现有敌人受击体容量准备，重复接触由 Application 截止。
- 投射体实际到达位置驱动特效与碰撞盒。先按场景阻挡截断路径，再上报敌人候选。Blaze Charge 使用现有 `CharacterController` 走计划位移，输出实际起止位移给扫掠。碰撞盒能跟随轨迹而不是只查两帧终点。
- 维持已有相机/角色/敌人/波次与 HUD 先后关系。主动取消、有效受击、死亡、波次转移、停用、卸载会作废批次。使用当前施放 ID 回传；终止后现有视觉可按源粒子生命周期清理，不能继续提交伤害。
- 选择时保持已验证的全局倍率所有权。MP 不足的面板状态走正常输入隔离与关闭逻辑。CombatHud 保持被动射线行为，选技继续用 WaveHud 的交互 Canvas。

## 4. 性能、配置和验收

- 初始化固定预告数组、四槽、按目录配置的预览/Animator Hash、粒子组件数组和物理查询缓冲。技能动作时间、蓝量、奖励 mutable 状态只在 Application。展示按快照变化刷新。
- 重复脚本导入以 GUID/哈希去重复制，保留每个导入资源的来源、目标、用途和有意适配说明。源工程只读。隔离验证通过后由明确清单安装至主工程，安装前记录哈希和可回退副本。
- 配套 `ui/combat-mana` 只修改 HUD 展示与其规格 R10。通过当前 `PlayerCombatStatus` 还原单向依赖。C1 公开签名不冲突，C2 无存档，C3 只读 MP 字段，C4 两模块各自资产责任已确认，C5 既有共享入口保持兼容，0 冲突。
