## 核心设计

### 架构总览

新增场景内的 `WaveRun`，管理波次进度、奖励与结局。它复用 `EnemyPopulation` 的名额和候选采样，接收 `EnemyHealth` 的归零结果，调用 `PlayerActions` 应用属性。选择界面只读取快照与提交按钮意图。保留现有程序集依赖。

另一方案是把波次和奖励合入 `EnemyPopulation`。它也能复用名额，但会使现有生成类同时依赖玩家属性、终局与抽奖。用户选定独立局内写入口。

### 关键类型

| 类型 | 层 | 职责 |
|---|---|---|
| `WaveDefinition`、`WaveReward` | Domain | 描述正整数配额、有限正间隔、奖励类型和等级 |
| `WaveRewardPool` | Application | 验证和快照奖励配置，按固定随机源生成三种不同组合 |
| `WaveRun`、`WaveStatus` | Application | 维护阶段、击败与配额。由阶段守卫选择和重开，输出只读快照 |
| `EnemyPopulation`、`EnemyHealth`、`PlayerActions` | Application | 继续持有占位、敌人生命和玩家战斗结果，增加局内结算所需入口 |
| `WaveSettings` | Presentation 配置 | 序列化十波和各级奖励数据。在开始时读取为运行时快照 |
| `EnemySpawner`、`EnemyActor` | Presentation | 校验 City、生成和移除对象，绑定实例生命，晚于双方伤害处理推进局内流程 |
| `RiccaPlayer`、`WaveHud` | Presentation | 交接键鼠输入，观察死亡演出，渲染和提交选择与重开 |

### 接入点和数据流

- `EnemySpawner` 使用序列化 `WaveSettings.asset` 在场景内创建一份 `WaveRun`，继续使用 `EnemySpawn.asset` 的距离、安全检查与尝试参数。
- 现有 Demo 场景绑定独立 `WaveHud.prefab`。用 UGUI、项目现有 TMP 字体、GraphicRaycaster 与场景唯一的 EventSystem。界面文字沿用现有 HUD 的英文风格，最后奖励为 `Final Reward`，死亡结果为 `Run Over`，通关结果为 `Run Complete`，重开按钮为 `Restart`。保留现有战斗 HUD。
- 配置 → Application 校验并取快照 → 生成器检查场景候选，申请和确认名额 → 敌人 HP 归零向本局报告 → 本帧战斗完成后进入奖励或死亡 → UI 读取状态 → 选择命令验证并向玩家写入 → 前进或通关。所有数据存在场景内存。

| 顺序 | 工作 |
|---|---|
| 1 | 先写可注入随机源与时钟的 EditMode 规则测试，再实现波次、抽取和玩家属性结算 |
| 2 | 接入刷怪、敌人生命、现有输入和死亡动画 |
| 3 | 用 Editor API 写入配置、预制体和场景接线，编译与实际场景验收 |

## 详细设计

### 1. 架构设计

`Game.Domain` 不引用引擎或上层。`Game.Application` 依赖 Domain。`Game.Presentation` 使用已声明的 Application、Domain、UGUI 和 TMP。无需新程序集、包或持久化服务。旧 `EnemyPopulation`、`IEnemySpawnCommands` 和 `IPlayerCommands` 调用方保持有效。独立测试和非波次场景可沿用原接口。

### 2. 数据结构与契约

默认配置由用户确认。

| 波次 | 同屏上限 | 刷怪间隔（秒） | 总敌人数 |
|---|---:|---:|---:|
| 1 | 3 | 1.5 | 3 |
| 2 | 3 | 1.4 | 4 |
| 3 | 3 | 1.3 | 5 |
| 4 | 4 | 1.2 | 6 |
| 5 | 4 | 1.1 | 7 |
| 6 | 4 | 1.0 | 8 |
| 7 | 5 | 0.9 | 9 |
| 8 | 5 | 0.8 | 10 |
| 9 | 5 | 0.7 | 11 |
| 10 | 6 | 0.6 | 12 |

| 奖励 | 类型权重 | Lv.1 | Lv.2 | Lv.3 |
|---|---:|---:|---:|---:|
| 血量 | 45 | +10 | +20 | +30 |
| 攻击 | 45 | +4 | +8 | +12 |
| 技能 | 10 | 占位 | 占位 | 占位 |

每级平分类型权重。九个组合加权无放回抽取三个。每波用新的选项组标识。技能仍是一张可选的卡，选择后发布类型与等级。血量以等量增量增加当前与上限，普攻按原伤害加成相加。配置与基准数值在开局验证最坏情况下十次叠加仍可表示。

| 接口 | 参数与结果 | 调用方向与契约 |
|---|---|---|
| `WaveRun.Status` | `WaveStatus` 值快照，含波号、阶段、组标识和三个只读奖励 | Application → Presentation |
| `WaveRun.CanSpawn(now)` | `double -> bool` | 生成器先快速查询，预约时再次验证阶段、节奏、配额与场上上限 |
| `WaveRun.TryReserveSpawn(..., now, out slot)` | 原物理报告、时间 → 预约 ID | Presentation → Application。原位置和敌人类型校验继续由现有生成服务执行 |
| `WaveRun.ConfirmSpawn(slot, health, now)` | `ulong, EnemyHealth, double -> bool` | 绑定一份有效且存活的生命对象。每个槽和同一个生命对象只确认一次。成功生成后设置下次允许时间 |
| `WaveRun.Release(slot)` | `ulong -> bool` | 失败预约或实例实际销毁时调用。释放和脱离生命回调至多一次 |
| `WaveRun.Advance()` | 无 | EnemySpawner 在两方伤害结算后调用。先核对 Ricca 存活，再处理清波 |
| `WaveRun.TryChooseReward(offerId, index, now)` | `ulong, int, double -> bool` | 检查玩家存活、阶段、当前组和索引。先提交属性与阶段，再通知技能扩展 |
| `WaveRun.SkillRewardSelected` | `event Action<WaveReward>` | Application 扩展点，仅有效技能选择触发。当前无需订阅者 |
| `WaveRun.TryBeginRestart()`、`CancelRestart()` | `bool`、`void` | 终局进入重载状态后拒绝重复命令，加载请求失败可回到原终局 |

存档分区、字段及迁移均为零。三种敌人保持当前资源引用与开局优先级。配置有效但起始波上限较低时，首波仍优先尚未成功生成的类型，直到用完本波总数。第 2 波起随机采样。

### 3. 交互流程

1. `RiccaPlayer.Awake` 构造既有战斗状态。`EnemySpawner.Start` 检查引用、导航和配置，完成场景注册与本局初始化。HUD 在初始化完成前隐藏。可选波次资产未赋值或波次表为空时沿用既有刷怪。非空配置非法时记录明确错误，本次波次保持未就绪。正确接入的 Demo 由资产测试保护。
2. 波次模式创建唯一的 EnemyPopulation，以十波最大上限作底层总容量，WaveRun 按当前波上限另外拦截每次预约。每波第一个预约可立即调度。实际实例创建与绑定成功后开始等待配置间隔。失败候选沿用每帧最多两次、每批限制尝试数的检查，失败批次延至下一间隔。尚未确认的候选和未击败敌人共同占用配额。任意时刻只允许新增到该波总量，该限制为已击败数加仍需结算的预约和活敌。绑定失败按实例退休及实际销毁回收；提前移除返还配额。
3. `EnemyHealth` 首次归零时通知关联的 slot。归零与实际销毁分别记录一次。名额管理可用现有 slot 字典保存生命引用与状态，复用一份回调。切波时已归零实例继续占用物理名额，释放只反映场上占位。当前波总击败达到预期时在帧末生成奖励。若 Ricca 同帧归零，直接进入死亡。
4. `EnemySpawner` 以顺序 150 的 `LateUpdate` 提交阶段，位于 `EnemyActor` 的 100 和战斗 HUD 的 200 之间。奖励、死亡和通关阶段，Application 冻结移动、攻击与后续敌方伤害。Ricca 继续执行动画和本地卡肉恢复，镜头不接收玩家输入，鼠标释放。窗口焦点、Esc、替代设备、相机绑定和回游戏时均通过同一可操控状态判定。选完当帧的 UI 点击不可转为战斗输入，下一帧才恢复捕获。
5. 死亡时当前 HP 保持 0，波号回到 1，最大 HP、攻击增量和待选奖励重置。等待死亡状态完成，Animator 缺失或停滞时用 12 秒非缩放时间限时，避免重开入口永久隐藏。通关可立即显示重开。重开通过场景构建索引请求重新载入当前 Demo。若请求当即失败，按钮恢复并显示失败状态；已接受的 Unity 载入操作在 15 秒未结束时改显示 `Reload delayed`，继续拒绝重复请求。
6. 禁用生成器时停止出怪和导航，先让实例退休并释放原名额。重新启用的同一实例继续原局。只在同一场景的加载生命周期内保留玩家绑定。销毁实例时停止回调，释放事件连接。奖励卡片和重开按钮监听成对装拆。用户可停在选择或结果面板直到主动操作。

### 4. 性能和边界

- 随机源、目录、选项数组、每帧物理缓冲和委托在初始化或绑定时建立。奖励抽取扫描固定九项。UI 以阶段或选项组变化为刷新条件，数值用 TMP 数字参数或预分配缓冲。现有实例化与角色生命周期仍可分配，稳态检查每帧 0 B 是目标。
- 校验恰好十个正数配额与有限间隔，奖励权重为正且技能较低，三个血量和攻击值递增。使用可表示范围检验累加，检查非法或倒退时钟、未知 slot 和过期组标识。
- 一次归零只计一次。过场零生成，候选失效可重试。上限降低时等待旧实例完成。合法场景暂时无路径时保持当前波，玩家可换位置。重开等待由玩家触发，死亡动画检测有超时。
- 场景内不增加静态波次或奖励状态。原有 `EnemyTarget` 注册与解绑、场景名额唯一性、NavMesh 生命周期照常执行。

### 5. 架构约束遵守声明

- [x] 无反向层依赖，本地 Application 唯一写入口。
- [x] 外部配置、时间、槽位、选择和重复重开均有守卫。
- [x] 生命回调与按钮订阅成对，旧场景引用随实例卸载。
- [x] 无存档变更。计时、卡肉和死亡退路可测。
- [x] 稳态不引入轮询分配，沿用每帧寻路检查预算。

### 7. 风险与契约终检

| 风险 | 应对 |
|---|---|
| 无效候选或外部销毁导致清波卡住 | 只以真实归零计数。预留失败与未击败移除后归还配额 |
| 受伤、死亡、卡肉或 UGUI 抢输入 | 只在帧末裁定清波。独立恢复 Animator 与鼠标。覆盖死亡优先和模态焦点 |
| Demo 场景正在编辑 | 独立 Unity 验证工程制作资产。安装前核验最新源哈希，备份后只安装明确范围 |
| 工作区无 Git 元数据 | 本地文档以源文件与 SHA-256 记录待审内容。保留变更清单与备份供对齐 |

C1 保留共享战斗和生成签名。C2 无存档。C3 新增独立配置资产，保留旧字段。C4 原资源 GUID 保留，仅添加引用。C5 Application 类型调整可由现有调用方继续使用。复查 `core R1` 的默认首波三种阵容、`ui R10` 的初始 HP 与 `gameplay R10` 的局部卡肉，行为均可继续成立。
