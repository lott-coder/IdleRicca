## 核心重点

### 架构总览

新增独立的 `PlayerSkillSet` 保存四槽、等级和技能定义。`PlayerActions` 协调选择、施放、普攻互斥和伤害。`WaveRun` 先筛选可生效的奖励，再在同一领取命令内提交技能和波次状态。Unity 提供输入、UI、时间倍率、动作、受击体和特效。沿用现有程序集。

另一方案是把四槽和等级规则直接放进 `PlayerActions`。它可少一个类型，但扩大现有普攻状态机的责任并增加测试耦合。用户确认独立技能状态方案。

| 类型或文件 | 层 | 责任 |
|---|---|---|
| `SkillId`、`SkillDefinition` | Domain | 穷举技能标识、三个等级的正伤害、归一化攻击窗口 |
| `PlayerSkillSet` | Application | 验证并快照四项配置，管理四槽、奖励前预览、授予及升级 |
| `PlayerActions`、`IPlayerSkillCommands`、`SkillStatus`、`SkillCast` | Application | 命令与快照，拥有选择编号、当前攻击批次、命中去重、技能与普通攻击互斥 |
| `WaveRun`、`WaveRewardPool` | Application | 抽取前按资格筛选技能，领取命令交给技能状态，继续发布既有通知 |
| `RiccaSkillSettings`、`RiccaPlayer`、`SkillHitbox`、`SkillSelectionHud` | Presentation | Unity 资产接线、输入和时间还原、动画及碰撞查询、四槽 UGUI |
| `EnemyTarget`、`EnemyActor`、`WaveHud` | Presentation | 现有敌人反馈消费技能伤害，波次奖励显示可授予或可升级的内容 |

### 接入点

- `RiccaPlayer.Awake` 从技能配置构造 Domain 快照并接给 `PlayerActions`。`EnemySpawner` 仍以同一个玩家对象创建 `WaveRun`。技能配置未绑定的旧场景保留现有入口与规则。City Demo 必须绑定有效技能配置、面板及 Collider 层。已绑定的配置校验失败时显性停止当前角色初始化，由 EnemySpawner 拒绝启动本局。
- 配置在 `Assets/Config/Gameplay/RiccaSkills.asset`。面板预制体挂现有 Demo UI 树，复用 UGUI 和同一个 EventSystem。Ricca prefab 与 Animator controller 添加四个技能动作和特效锚点。
- 奖励资产仍使用 `WaveSettings` 的三级权重配置。既有动画资源路径、普通攻击设置字段和序列化引用继续有效。无新增持久化分区。
- 技能数据和施放状态均随场景。Application 的选择编号与攻击批次不跨实例使用。UI 通过命令和只读快照访问。

### 核心数据流

技能配置 → Application 快照 → WaveRun 抽取资格和奖励预览 → 成功领取后提交槽位及波次 → F 提交选择命令 → UI 显示槽位并按状态减速 → 点击提交选择编号和槽位 → Application 快照施放数据 → Unity 复速并播放 → 生效窗口内提交敌人候选 → Application 扣血 → 现有受击、死亡、击败计数。

## 详细设计

### 1. 架构设计

`PlayerSkillSet` 只处理技能定义与成长。单个 `PlayerActions` 已持有 HP、普攻和攻击批次，使用同一个攻击批次所有者保证同一时间只有一个攻击动作。底层可共用区间截取和命中去重，入口验证当前动作类别，避免旧普攻接口提交技能批次。`IsAttacking` 继续表示普通攻击，新增只读的 `IsCastingSkill`。WaveRun 通过既有 `PlayerActions` 依赖查询并写入局内奖励，`WaveRewardPool` 仍只抽取数据。

### 2. 数据结构

四槽按索引 0–3 排列。奖励优先按配置目录顺序找到首个未装备技能，放入第一个空槽，初始等级等于奖励等级。满槽时选择最低等级且未满级的技能，同级取最低槽位索引，新等级为 `max(oldLevel + 1, reward.Level)`，上限 3。目录固定四个不同技能，三个等级的伤害严格递增。候选皆无收益时，抽取目录中只使用六个属性组合，继续按原权重无放回抽三张。

技能 UI 快照按值返回四格，不向 UI 暴露可写数组。选择编号每次成功打开才增加，关闭、受击与阶段切换后旧编号失效。施放快照记录技能标识、等级、伤害、窗口和独立施放编号。Unity 按技能标识查找启动时验证过的表现数据。

| 契约 | 参数与返回 | 调用与语义 |
|---|---|---|
| `PlayerActions.SkillCommands`、`SkillStatus` | `IPlayerSkillCommands`、值快照 | 暴露技能命令或四槽、选择 ID、状态、可用标志。旧场景可读取未启用状态 |
| `TryOpenSkillSelection()` | `bool` | 仅在 Application 的 CanControl 为 true 且角色没有普通攻击、在途技能或已打开选择时接受。空槽也接受 |
| `CancelSkillSelection(selectionId)` | `ulong -> bool` | F、Esc 或 UI 关闭入口用当前 ID。取消不改四槽与等级 |
| `TryCastSkill(selectionId, slot, now, out cast)` | `ulong, int, double, out SkillCast -> bool` | 在 Application 再次校验 CanControl、当前选择 ID、合法可用槽位、有限且不倒退的游戏时钟和动作空闲，消费选择并提交本次施放快照 |
| `BeginSkillFrame / TryHitSkill / EndSkillFrame` | 施放 ID、当前状态命中和进度 → 认可的 `AttackSampleBatch`，批次和 `EnemyHealth` → `AttackHit`，批次 → 是否完成 | 仅允许当前技能批次且 CanControl 为 true。终止状态、错误动作或过期批次拒绝。有效伤害复用敌人生命结算 |
| `WaveRewardPool.Draw(destination, includeSkill)` | 原缓冲区，`bool` | 保留现有 `Draw(destination)` 入口。有效技能配置下，满级前按原权重，满级后禁用技能 |
| `WaveRun.TryGetSkillRewardPreview(offerId, index, out preview)` | `ulong, int, out SkillRewardPreview -> bool` | 查看当前组技能名、目标槽及等级变化。无技能配置、过期组及属性卡返回 false |
| `WaveRun.TryChooseReward`、`SkillRewardSelected` | 既有签名 | Application 在波次推进前尝试写入技能奖励。任何有效技能奖励提交成功后照旧发布原始奖励通知 |

可施放状态不依赖 UI 文案。选择另有输入守卫，敌人仍能伤害选择中的 Ricca。既有普通攻击加成只加到普攻，连击沿用 UI R11 的普攻计数。EnemyTarget 和 EnemyActor 提供技能结果路径，复用受击及死亡反馈，省去普攻卡肉。普攻的非缩放卡肉时钟完全沿用。

### 3. 交互与生命周期

1. Demo 启动时，技能配置校验 ID 唯一、四项数目、伤害递增、`0 ≤ start < end ≤ 1`、动画片段非循环、时长及盒几何有限且为正。验证 Animator 状态引用、层掩码与面板接线。合法绑定构造四槽运行状态。绑定后校验失败时记录具体问题并停止角色及波次初始化。未绑定的旧场景则继续正常初始化，仍以相同权重抽取同种子占位卡，原有技能通知照常发布。Demo 资产检查把缺失配置设为失败。
2. 清波时先查询技能资格再抽取。WaveHud 在技能卡上标明授予名称与目标等级，已有技能升级时显示等级变化。领取命令先核对当前组、索引和技能资格，能确切应用时才消费本组。配置场景若资格检查失败，槽位、组号、阶段和时钟均维持。技能写入成功后推进波次，然后照旧通知。归零时清除本局技能，最后一波成功领取后直接进入通关。
3. F 打开选择前验证输入确实来自当前操控路径，且 Unity 游戏速率与固定步长均为有限正值。已暂停时不打开选择。获准后同帧抑制移动、视角和普攻。用户确认默认倍率为进入面板前 `Time.timeScale` 的 **20%**。有至少一个可施放技能才取得倍率所有权。同步乘同一倍率调整 `Time.fixedDeltaTime`，保存两个此前值。UGUI 点击和取消仍按帧处理。空槽面板接管鼠标但保持原速，展示获取途径及 F / Esc 关闭提示。可用槽展示名称、等级和攻击方向或范围。
4. 点击、取消、受击、失焦、波次阶段变化、组件停用和卸载汇入同一退出逻辑。开始施放前再次检查还原后的游戏速率，暂停状态下取消派发。任何减速所有权只释放一次并还原两个原值。空面板退出跳过时间写入。有变化时 UI 按快照同步，阶段切换在 `EnemySpawner.LateUpdate` 交接。结束帧隔离设备输入，下一可操控帧恢复光标。选择状态只锁输入，伤害入口仍处理有效敌人命中和死亡。
5. 施放开始先恢复全局时间，清零选择态，再用 Animator 的独立非循环状态从 0 播放并求值。保留起手角色朝向和中心。期间水平移动、普攻和 F 新选择受动作守卫，镜头在关闭面板后按既有规则行动。VFX 按配置进度发出一次，取消时清理。本次动画完成后回到待机，失去 Animator 或没有进度则取消。动画未能进入或发生停滞时使用有限的游戏时间看门狗，预算为片段时长的两倍加 0.5 秒。非有限或倒退报告拒绝并释放当前技能。施放期间若游戏速率变为零或无效，表现桥接立即请求取消，避免游戏时间看门狗停摆。
6. 已固定几何的技能在起手角色位置和朝向下以盒体查询。成功开始时进度从 0 起算，持有非循环技能状态到应用层消费最终批次，允许在同一个批次先查询窗口再结束动作。只要有效动画采样区间和窗口相交就查询，低帧率跨过整个窗口也结算。窗口外报告、墙体与场景装饰、已归零敌人及多 Collider 重复目标均不得扣血。按照敌人生命对象去重，现有 EnemyTarget 只将候选交给 Application。
7. 同帧顺序保持 Ricca 阶段提交 → EnemyActor → 波次 → HUD。PlayerActions 收到有效伤害在同一次状态写入内取消选择和施放，作废当前选择和攻击批次。SetWaveControls(false) 同步执行相同的清理，独立于 Unity 更新顺序。波次裁定继续保留死亡优先。重开构造新场景状态与四槽，停用或卸载先使批次与选择 ID 失效，再还原时间、光标和表现。

### 4. 首版动作与性能

| 技能 | 盒体中心和尺寸，单位米 | 归一化生效窗 | 三级伤害 | 原创占位动作与特效 |
|---|---|---|---|---|
| Quick Cut | 前向 0.95，宽 1.6、深 1.9、高 1.8 | 0.30–0.48 | 34、46、60 | 短促近身斩，约 0.60 秒 |
| Thrust | 前向 1.65，宽 0.9、深 3.3、高 1.8 | 0.38–0.58 | 38、52、68 | 前刺，约 0.75 秒 |
| Sweep | 前向 1.1，宽 3.4、深 2.2、高 1.8 | 0.30–0.62 | 29、40、54 | 横扫，约 0.85 秒，加入弧形粒子 |
| Ground Burst | 水平居中，宽 3.0、深 3.0、高 1.8 | 0.54–0.71 | 32、45、60 | 下劈和脚下冲击，约 1.05 秒，加入环状粒子 |

中心高度均为 0.9 米。模型姿态、可视边界和窗口在 PlayMode 以当前骨架和场景相机校准。特效场景实例启动时准备，每种一个，动画片段与质量差异通过 Inspector 调整。

- 角色和 UI 启动时缓存状态 Hash、按钮和回调，四格标签仅在快照变更时更新。物理查询复用 `EnemyTarget` 缓冲与已有受击体注册。Application 的命中集合在绑定波次配置时按可配置最大同屏量准备。
- 计时和标签查询使用值类型，常态更新不分配托管对象。既有生成容量和 prefab 实例化成本按当前规程记录。特效不参与敌人候选或伤害状态。
- 临时方案及回退留在技能配置与 Demo 资源接线。本设计未引入网络或存盘变化，也不迁移旧 [SerializeField]。其他合法调用继续使用现有构造和接口。

### 7. 风险

| 风险 | 处理 |
|---|---|
| 技能奖励仍为低权重，普通一局前几波可能拿不到 | 保留现有随机权重，单独记录试玩时首次出现和施放波次。用固定随机序列验证四槽和升级 |
| 领奖与技能选择争抢光标 | 由 Ricca 的一个输入交接处理 F、Esc、奖励阶段和焦点。所有退出分别测到恢复 |
| 物理跨过短生效窗或旧批次漏作废 | 以区间相交和批次 ID 防御，L1、L2 同时覆盖 |
| 动画、盒与特效不对齐 | 已校验片段绑定，使用真实模型录屏核对窗口，配置允许独立调参 |
| 现有目录缺少 Git 元数据 | 设计与增量保存在当前 `_tmp`，契约冻结提交需有 Git 检出，已记录到问题表 |
