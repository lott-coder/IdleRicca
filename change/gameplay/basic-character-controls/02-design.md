## ★ 核心重点（一目了然区）

### ★1. 架构总览

复用现有四层程序集。Presentation 采集键鼠、驱动镜头和角色物理、提交刀刃与敌人碰撞的报告。Application 持有攻击阶段和每挥击命中记录，裁定移动许可与伤害。Domain 处理纯 C# 输入向量与 HP 规则。

两个已比较的方案分别是按动画进度对随剑盒补采样，以及通过动画事件控制触发器开关。用户选择进度采样。Unity Editor 从原片段的有效区间烘焙剑盒轨迹，运行时按 Animator 进度取该区间的真实中间姿态。每一段先完成命中结算，再推进攻击状态。原普通攻击片段保持原样。

### ★2. 关键类型清单

| 类型 | 层 | 职责 | 依赖 |
|---|---|---|---|
| `MovementDirection`、`HitPoints` | Domain | 净化平面移动输入并限制斜向幅度，保护 HP 下界 | 纯 C# |
| `PlayerActions`、`EnemyHealth` | Application | 接收控制命令，确定移动许可、挥击阶段及每目标结算，提供只读 HP | Domain |
| `RiccaPlayer`、`ThirdPersonCamera` | Presentation | 键鼠读入、角色胶囊移动及动画、跟随及遮挡、光标生命周期 | Unity、Application |
| `SwordHitbox`、`EnemyTarget` | Presentation | 随武器轨迹的盒查询、Collider 身份映射、敌人消失 | Unity、Application |
| `NormalAttackSettings`、`EnemyHealthSettings` | Presentation 配置 | 可调伤害和有效窗口、各敌人初始 HP | ScriptableObject |

### ★3. 接入点

- 保留 `Game.Domain` 不含 UnityEngine，`Game.Application` 引用 Domain，`Game.Presentation` 引用 Application。测试程序集按实际覆盖声明引用。
- Demo 场景用序列化引用把原 Main Camera 绑定到 Ricca 实例。角色本体、剑身形状和敌人受击体存入对应 prefab。
- 攻击与单敌 HP 各用独立配置资产，分别从 Ricca 和敌人 Inspector 可访问。运行时状态随所在场景初始化。
- 保留现有 `Moving`、`Attack` 入口及 Idle、Move、Attack 状态。Ricca 的 Move 使用行走和奔跑的 Blend Tree。玩家请求时设置 `HoldAttack`，用 `Animator.Play` 从 Attack 的进度 0 直接起手，确保画面和查询使用相同的动作，即使窗口从 0 开始也成立。末次批次消费完后主动向 Idle 淡出。旧 `Attack` 触发器保留原进入过渡，`HoldAttack` 默认关闭，仍可自动退出到 Idle。

### ★4. 核心数据流

键鼠输入 → 方向和攻击命令 → Application 移动许可 → CharacterController 与 Animator → 剑身盒在有效区间内检查重叠 → Application 去重与扣血 → EnemyTarget 在 HP 归零的同次结算禁用目标根对象。

## 详细设计（补齐区）

### 1. 架构设计

#### 1.1 模块定位

gameplay 新增玩家操控和普通攻击，core 持有 Demo 构建入口及环境基础设施。城市设计与在途增量只涉及场景、环境、照明、角色实例及原 Animator 入口。gameplay 保留旧 GUID、路径、相机和旧 Animator 状态，原 Attack 回 Idle 的途径仍存在。玩家保持移动键时，Idle 之后按输入继续到 Move。

#### 1.2 类型结构

| 对象 | 所有权与数据 |
|---|---|
| 玩家实例 | 一份 `PlayerActions`，有空闲、等待 Attack 动画、正在挥击三种状态。每次开始新攻击清空受击目标集合。 |
| 敌人实例 | 一份 `EnemyHealth`，初始化时读取配置；外部可读 HP 和存活，扣血只经 Application。 |
| 相机 | 场景原有 Main Camera，跟随角色根节点及肩部上方偏移。只累计有限的偏航和俯仰，遇到环境遮挡时缩短跟随距离。 |
| 剑身 | 沿 weapon 本地剑刃安装可视化调节的 BoxCollider，保持组件禁用，仅用于定义查询几何。由 Unity Editor 采样得到相对 Ricca 根的盒中心、旋转、半尺寸。 |

#### 1.3 依赖方向

Presentation → Application → Domain。无新的运行时依赖或输入包。复用项目 InputManager 的 Mouse X/Y，WASD 与两侧 Shift 使用按键状态，左键使用按下边沿。

### 2. 数据结构

#### 2.1 核心类型

- `MovementDirection` 输入是镜头偏航与前后、左右轴，输出平面单位方向。归一化确保斜向速度上限相同。
- `HitPoints` 是整型，初始化范围为正，受伤后最低为 0。独立配置的默认值为普攻 25、各敌人 100。
- 跑步和步行初值分别为 4.5 和 2.1 米/秒，可按世界比例在 Inspector 微调。旋转、俯仰和相机投影使用有界参数。
- 动画 `rc_stand_normalAttack_01` 为 60 fps、约 70 帧。按 prefab 层级和已导入骨骼曲线采样，剑尖在第 14 到 22 帧从右后上方扫过正前方，随后进入收招。起始有效区间为进度 14/70 到 22/70，在 Phase 4 用 Unity 的实际 Animator 姿态复核。
- `NormalAttackSettings` 检查伤害为正整数，窗口有限且满足 0 ≤ 开始 < 结束 ≤ 1，轨迹有有效端点、时间严格递增、盒尺寸为正。Inspector 编辑窗口后须重新烘焙轨迹。每个 `EnemyHealthSettings` 检查初始 HP 为正整数，并在敌人初始化时将该值复制到运行时状态。玩家绑定时一次性读取并验证配置，伤害和窗口以只读快照交给 Application。

#### 2.2 接口 / 事件契约（C1）

| 调用 | 方向 | 语义 |
|---|---|---|
| `TryStartAttack()` | Presentation → Application 命令 | 空闲才接受一次点击，立即禁止水平移动；动作进行期间再次点击返回拒绝。 |
| `GetMovement(float x, float y, float yaw, bool running)` | Presentation → Application 查询 | 返回世界平面移动意图；攻击时为零。 |
| `BeginAttackFrame(attackState, normalizedTime, deltaTime)` | Presentation → Application 命令 | 验证当前 Attack 实例的单调进度，返回带本挥击编号与本帧编号的批次。无有效区间交集时才关闭伤害提交，进度仍由 `EndAttackFrame` 提交。未进入 Attack 状态时返回无批次。 |
| `TryHit(AttackSampleBatch batch, EnemyHealth target)` | Presentation → Application 命令 | 仅接受当前开放批次里的活目标。一挥内首次提交时扣血，返回是否命中与是否刚归零。旧批次、伪造批次、重复目标或篡改区间均不结算。 |
| `EndAttackFrame(AttackSampleBatch batch)` | Presentation → Application 命令 | 关闭当前批次。已消费到动画末尾时才结束本挥、解除移动锁、释放 Animator 的 `HoldAttack`。取消可立即作废批次与状态。 |
| `CurrentHp` | Application → Presentation 查询 | 供测试与表示读取，写入口在 Application 内部。 |

#### 2.3 存档影响（C2）

状态只在场景内存活。复用或重新载入 Demo prefab 时按配置产生新的会话 HP，既有存档分区和读取无变更。

### 3. 交互流程

#### 3.1 时序

1. 首次聚焦后锁定并隐藏光标。失焦或组件退出时释放；手动解除锁定后再次抓取光标的点击只恢复操控。
2. 每帧读取鼠标增量和按键。鼠标 yaw/pitch 驱动独立相机，移动方向使用水平 yaw。胶囊在水平意图之外处理接地和重力。
3. 左键经 Application 接受后，将 `HoldAttack` 设为真，立即从进度 0 播放 Attack，锁水平移动与当前角色朝向，镜头和重力继续。读当前 Attack 状态的进度，从本挥零点累计。首个有效采样即使已跨过整个有效窗口，也能使用缓存补齐。未能进入 Attack 的等待上限为 0.5 秒。
4. Animator 求值后在 LateUpdate 开批次。按裁剪后的两个边界和其间烘焙的中间姿态查询，使用动画进度；将轨迹的局部位置通过当时插值的角色根位姿变换到世界。Editor 在有效窗口内最多隔半帧采一次，此段约 17 个原 clip 采样点，并按相邻盒的位移与转角继续加密。每个批次的硬上限为 128 次查询，烘焙验证窗口内完整轨迹连同两个边界必须能在此预算内完成。若采样工具无法满足约束，明确拒绝产生可用配置。
5. 剑盒是查询几何，禁用挂载的 BoxCollider。通过受击体 Layer 与 `QueryTriggerInteraction.Collide` 执行盒重叠检测。活动的受击 Collider 在绑定时登记到所属敌人实例，使用缓存与非分配查询。所有接触提交完后关批次。掉帧跨过动画末尾时，`HoldAttack` 让 Attack 状态仍可读取，采样进度上限取 1。末次关批次后主动淡出到 Idle，下一帧按当前输入恢复移动。
6. 归零时立即禁用敌人根对象，其渲染、碰撞与 Animator 同时退出；重新载入场景产生新对象和 HP。

#### 3.2 生命周期

Awake 初始化单体和缓存组件。Start 启用已序列化的场景引用及输入。敌人注册与反注册成对，禁用即移除受击盒条目。相机持续跟随期间每帧只应用自己的已绑定目标。

#### 3.3 错误处理与兜底

| 条件 | 行为 |
|---|---|
| 轴值、角度或状态进度无效 | 忽略该输入或限制到合法范围。 |
| 输入已接受但 Animator 未进入 Attack | 有界等待后结束该次攻击，只恢复可移动状态。 |
| Attack 进入后被外部中断或玩家实例停用 | 关闭批次并清理状态，同时释放 `HoldAttack`。后续可开始独立的新挥击。 |
| 缺绑定或配置非法 | Editor 验证拒绝无效资产。启动时可诊断地停用对应输入或结算。 |
| 查询已被禁用 / 已归零敌人 | 忽略，健康状态保持。 |

### 4. 性能与防御性设计

#### 4.1 分配预算

常驻分配为玩家对象、三份敌人状态、受击体映射、攻击命中集合及可复用的重叠缓冲。用 Profiler 或等效数据采样稳定静止、移动与有效挥击三个区间，区分场景启动与稳态帧。

#### 4.2 性能红线

`Update` 和 `LateUpdate` 使用预缓存引用、动画哈希及数组。只有有效挥击时做重叠查询，专用 Hurtbox Layer 排除环境碰撞。采样数由烘焙资产长度收敛在每挥既定上限；受击盒数量在绑定时确定缓冲容量，避免查询截断遗漏目标。

#### 4.3 防御性编码

命中以敌人实例为身份，针对多碰撞体去重。清除或退出攻击后无旧状态结算。新一击可重新命中存活对象。先更新权威 HP 再即时禁用可视对象。

#### 4.4 内存/实例预估

一套 Ricca 输入、移动、剑盒与相机逻辑。三个现有敌人分别持有可配置的受击体和状态。配置资产为少量数值。

### 7. 风险评估

| 风险 | 应对 |

| 低帧率造成刀刃穿过受击体 | 从实际动画烘焙姿态并裁剪有效区间，以可控预算按轨迹补采样，验证弧线中间命中和直线误判用例。 |

| 角色胶囊与场景姿态不匹配 | 在 City 物理场景按实际地面、台阶、墙和角色比例校准，保留原预制体序列化连接。 |
