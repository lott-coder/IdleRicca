# 无人值守安全（`--unattended`）

> 本文是 `--unattended` 的**唯一权威**：严重度矩阵只在这里定义，其它文档引用它。
> 自治模式的前提不是"AI 够聪明"，而是**爆炸半径可控**。

版本：v2.0.0｜适用：`/workflow plan --unattended [--cron]`

---

## 1. 核心差异（与交互模式）

| 交互模式 | `--unattended` |
|---|---|
| Phase 1/2 的 brainstorm 问答 | 跳过，降级为 `--direct` |
| 方案选择（精简/标准/旗舰） | 自动选「标准」 |
| 审核后向用户确认 | 严重度矩阵自动决策（§2） |
| 用户确认进入下一阶段 | 自动（0 阻断 且 警告 < 5） |
| 修复决策 | 自修复循环（非安全类最多 2 轮） |
| 手动验证（L3/L4） | 一律标记 `unverified` |
| 归档 | **不自动归档**，只生成就绪报告 |

---

## 2. 严重度自动决策矩阵（唯一权威定义）

```
审核完成 → 解析严重度
  ├─ 含「安全阻断」？        → HARD STOP ✋（不进入自修复）
  ├─ 含普通阻断？            → 自修复 ≤2 轮 → 仍未过 → STOP
  ├─ 0 阻断 + 警告 ≥ 5 条？  → STOP（质量滑坡防护）
  ├─ 0 阻断 + 警告 < 5 条？  → 自动放行 ✓
  └─ 0 阻断 + 0 警告？       → 静默放行
```

跨阶段累计警告 ≥ 10 → 全局 STOP。

> `工作流执行.md` 不再重复本矩阵，只引用本节。

---

## 3. 安全阻断清单（出现即 HARD STOP，禁止自动修复）

| # | 类型 | 为何不可自动修 |
|---|---|---|
| 1 | 改架构权威模式 | 影响全部现有代码与验收标准 |
| 2 | 引入网络库 / 云存档 / 第三方 SDK | 依赖与运行环境变更，需人审 `manifest.json` |
| 3 | 修改 asmdef 的 references 白名单 | 分层是唯一硬约束，改它等于改地基 |
| 4 | 修改存档 schema 且无迁移代码 | 玩家存档不可读（不可逆） |
| 5 | 存档载入失败时静默用默认值 | 等于覆盖玩家存档 |
| 6 | 删除或移动任何资源（`.prefab`/`.asset`/`.unity`/`.meta`） | GUID 断裂，引用静默失效 |
| 7 | 修改 `ProjectSettings/EditorSettings.asset` | 全工程进入不可 diff 状态 |
| 8 | 修改 `Packages/manifest.json` / `packages-lock.json` | 依赖漂移 |
| 9 | 在 `Update`/`LateUpdate`/`FixedUpdate` 内新增分配 | 性能回归且难定位 |
| 10 | `catch (Exception) {}` 空捕获 | 掩盖故障 |
| 11 | 跨层反向依赖 | 编译即失败；用反射绕过更糟 |
| 12 | **修改测试以通过门禁** | 门禁失效（P0 验证自洽假象） |

> 判定规则：**只要"改错的后果不可逆或不可检测"，就是安全阻断。**

---

## 4. 运行约束（HARD STOP 条件）

| 约束 | 阈值 | 超限动作 |
|---|---|---|
| 单次自动生成文件数 | ≤ 10（不含 `05-issues.md` 与进度文件） | STOP |
| 单 Phase 耗时 | ≤ 30 分钟 | STOP |
| 单发现自修复轮次 | ≤ 2 | STOP |
| 单 Phase 总修复轮次 | ≤ 3 | STOP |
| WIP 无推进时长 | ≤ 24 小时 | 标记 `stale` + STOP |
| 并发执行 | 一个 `change/{module}/_tmp/` 同时只允许一个进程 | 取锁失败即退出 |
| **连续 Agent 报错** | ≤ 1 次重试 | 第 2 次失败 → STOP |

---

## 5. 绝对禁止

- ❌ `git commit` / `git push`
- ❌ 修改 `.unity` / `.prefab` / `.asset` / `.meta`
- ❌ 执行出包命令
- ❌ 删除任何文件
- ❌ 修改 `ProjectSettings/`、`Packages/`
- ❌ 跳过 `plan-reviewer` / `code-reviewer`

**允许**：读写 `Assets/Scripts/**/*.cs`、`Assets/Tests/**`、`docs/**`、`change/`、`spec/`、`knowledge/`。

---

## 6. Phase 判定（按 `_tmp` 文档存在性）

| 条件 | 当前 Phase |
|---|---|---|
| `00-prd-analysis.md` 存在但 `01-requirements.md` 不存在 | Phase 1 |
| `01` 存在但 `02-design.md` 不存在 | Phase 2 |
| `02` 存在但 `03-plan.md` 不存在 | Phase 3 |
| `03` 存在但未标记「全部完成」 | Phase 4 |
| `03` 全部完成 + code-review 已通过 | Phase 5 |
| `.unattended-progress.json` 有 `stoppedReason` | **SKIP**（等人介入） |
| `_tmp/` 为空 | **SKIP**（可能人工启动的 WIP，不处理） |

**模块处理顺序**：字母序（确定性）。多模块 WIP 串行处理，完成/停止一个再处理下一个。

---

## 7. 边界处理

| 场景 | 处理 |
|---|---|
| `_tmp/` 为空 | SKIP，不自动处理 |
| 并发 Cron 触发 | `change/.unattended.lock` 防重（<30min 拒绝，≥30min 接管） |
| 会话崩溃 | 锁过期后重入，从 `.unattended-progress.json` 恢复 |
| WIP >24h 无推进 | 标记 stale，`stoppedReason="stale-timeout"` |
| 审核结果为空 | 视为通过（无 findings = 无问题） |
| Agent 调用报错 | 重试 1 次 → 仍失败 → STOP，写 `05-issues.md` |
| 超过 10 个自动生成文件 | STOP（防失控） |
| 已存在 `stoppedReason` | SKIP，不覆盖 |

---

## 8. 可自动修复的范围（正面清单）

**可以修**：
- 文档文本修正（补全缺失章节、澄清模糊描述）
- 补类型注解 / 补 XML 注释
- 补输入校验桩代码（类型/范围判断）
- 补超时保护
- 修正常量命名、私有字段命名
- 补缺失的事件退订

**不可以修**（转 HARD STOP 或人工）：
- 存档 schema 与迁移逻辑
- 权威层与表现层的职责重划
- 资源/资产的增删改名
- 依赖与工程配置
- 任何需要人眼判断的视觉问题

## 9. 进度跟踪

写入 `change/{module}/_tmp/.unattended-progress.json`：

```json
{
  "mode": "unattended",
  "startedAt": "2026-11-12T10:30:00Z",
  "currentPhase": "phase3",
  "phases": {
    "phase1": {"status": "auto-passed", "completedAt": "…", "blockingFindings": 0, "warnings": 1},
    "phase2": {"status": "in_progress", "completedAt": null, "blockingFindings": 0, "warnings": 0}
  },
  "repairRounds": {"requirements": 0, "design": 0, "plan": 0, "code": 0},
  "autoGeneratedFiles": 3,
  "lastError": null,
  "stoppedReason": null
}
```

`stoppedReason` 枚举：`security-blocking` / `self-repair-failed` / `quality-guard` / `stale-timeout` / `agent-error` / `null`

---

## 10. 恢复流程

1. 读 `05-issues.md` 看阻断原因
2. 读 `.unattended-progress.json` 看停在哪个阶段
3. 人工修复（安全阻断还需人审方案）
4. 清空 `stoppedReason`
5. 重跑 `/workflow plan --unattended` 从当前阶段继续；或手工完成剩余阶段后 `/workflow archive`

---

## 11. 完成报告（强制）

执行结束写入 `05-issues.md`：

```markdown
## 无人值守执行完成报告
- 执行时间: {start} → {end}
- 模块: {module}
| Phase | 状态 | 阻断 | 警告 |
|---|---|---|---|
| P1 | auto-passed | 0 | 1 |
| P2 | auto-passed | 0 | 2 |
| P3 | stopped (self-repair-failed) | 2 | 0 |
- 阻断问题: {描述}
- 待人工: 1) 修复 P3 阻断 2) 重跑 /workflow plan --unattended 3) 或手动完成后 archive
```

---

## 12. `--cron` 轮询模式

| 项 | 定义 |
|---|---|
| 行为 | 每 N 分钟读 `change/versions.json`，对 `status=wip` 的模块按字母序处理 |
| 无 WIP 时 | 等待下一个周期，不退出 |
| 有 WIP 但已 STOP | SKIP（不覆盖 `stoppedReason`） |
| 退出条件 | 用户中断 / 累计 10 个文件上限 / 连续 3 次取锁失败 |
| 与单次模式差异 | 单次模式处理完当前 WIP 即退出；`--cron` 持续驻留 |

---

## 13. 并发锁

`change/.unattended.lock`，内容含模块名、PID、时间戳。

- 存在且 **< 30 分钟** → 拒绝启动（已有实例在跑）
- 存在且 **≥ 30 分钟** → 判定为残留，接管并警告
- 与 `change/.archive.lock` 是**两把不同的锁**（一个防重复规划，一个防重复归档）

---

## 14. 自动决策记录（强制审计）

所有自动决策写入 `04-review-report.md` 的独立章节：

| 时间 | 阶段 | 决策点 | 原交互 | 自动决策 | 依据 |
|---|---|---|---|---|---|
| 10:30 | P1 | 方案选择 | 精简/标准/旗舰 | 标准 | PRD 无旗舰信号 |

**没有记录的自动决策 = 违规**。

---

## 15. 何时才该用自治模式

| 适合 | 不适合 |
|---|---|
| 需求已明确（有 PRD 或等价描述） | 需求还在探索 |
| 改动集中在 Domain/Application | 改动涉及场景/prefab/配置资产 |
| 有测试可验证 | 只能靠肉眼看 |
| 单模块、低耦合 | 跨模块契约变更 |

> 一句话：**自治模式适合"已经被想清楚的事"，不适合"需要一起想的事"。**
